## A. Frontmatter品質

| # | チェック項目 | 判定基準 |
|---|------------|---------|
| A1 | **name** | lowercase + hyphens のみ。64文字以内。Skill の目的を端的に表現している |
| A2 | **description** | 3rd person で記述。What（何をするか）+ When（いつ使うか/トリガーフレーズ）+ Do NOT use for（ネガティブトリガー）を含む。1024文字以内 |
| A3 | **user-invocable** | Skill種別に適切か。オーケストレーター → `true`、タスク型 → 単独利用なら `true`、参照型 → 他Skillからのみ呼ばれるなら `false` |
| A4 | **context: fork** | タスク型（独立完結する作業）のみに設定されているか。オーケストレーター・参照型には設定されていないか。Forked Skill内でSkill tool / Agent toolの呼び出しを前提としていないか（隔離サブエージェントではこれらは使用不可） |
| A5 | **allowed-tools** | 必要最小限のツールのみ列挙されているか。不要なツールが含まれていないか |
| A6 | **Agent Teams agent-teams-guide** | Agent Teams（TeamCreate等）を使用するSkillの場合、SKILL.mdの前提セクションに `einja-common:agent-teams-guide` のSkillツール読み込み指示が含まれているか |

## B. 構造品質

| # | チェック項目 | 判定基準 |
|---|------------|---------|
| B1 | **500行以内** | SKILL.md body（frontmatter除く）が500行以内か |
| B2 | **Progressive disclosure** | 詳細情報が references/ に適切に分離されているか。SKILL.md に全情報を詰め込んでいないか |
| B3 | **参照1階層のみ** | references/ 配下にサブディレクトリがないか（`references/sub/` のようなネスト禁止） |
| B4 | **TOC** | 長い references ファイル（100行超目安）にはTOC（目次）があるか |
| B5 | **用語の一貫性** | 同じ概念に異なる用語を使っていないか（例: "Skill" と "スキル" の混在） |
| B6 | **時間依存情報なし** | 「現在」「最新」「2024年時点で」等の時間依存表現を含んでいないか |
| B7 | **具体例** | 抽象的な説明だけでなく、具体的な使用例・入出力例が含まれているか |
| B8 | **ワークフローステップ** | 手順が明確なステップとして構造化されているか。曖昧な指示（"適切に処理する"等）がないか |

## C. einja設計思想適合

| # | チェック項目 | 判定基準 |
|---|------------|---------|
| C1 | **専門知識不要** | ユーザーにIT・業界の専門知識を求めていないか。専門用語の入力や技術的判断をユーザーに委ねていないか |
| C2 | **平易な質問** | ユーザーへの質問は平易な言葉で、選択肢形式を優先しているか |
| C3 | **技術操作自動化** | 技術的な操作（git、API呼び出し、ファイル操作等）はすべてSkill内で自動実行されるか |
| C4 | **コンテキスト自律収集** | 実行コンテキスト（カレントディレクトリ、git状態、関連ファイル等）はSkillが自律的に収集し、ユーザーへの質問を最小化しているか |
| C5 | **エラーリカバリ** | エラー発生時にユーザーに技術的な対処を求めず、自動リカバリを試みる設計か。リカバリ不能な場合は平易な説明で代替案を提示するか |
| C6 | **視覚的確認** | 中間成果物の確認にスクリーンショットやプレビューなど視覚的な手段を優先しているか |
| C7 | **AskUserQuestion 2層記述** | AskUserQuestion の選択肢が `description`（何をするか）と `Note:`（選ぶとどうなるか）の2層で記述されているか |

## D. Anthropicベストプラクティス適合

| # | チェック項目 | 判定基準 |
|---|------------|---------|
| D1 | **簡潔さ** | Claudeが既に知っている情報（言語構文、一般的なライブラリの使い方等）を説明していないか |
| D2 | **自由度の適合** | タスクの脆弱性（ミスの影響度）に応じた自由度設計か。脆弱なタスクには具体的なステップ・バリデーションがあるか |
| D3 | **Windowsパス不使用** | `C:\` 等のWindowsパスを使用していないか。相対パスまたはPOSIXパスを使用しているか |
| D4 | **description明確性** | description が曖昧でないか。具体的なトリガーフレーズ・ユースケースが含まれているか |
| D5 | **スコープクリープなし** | 1つのSkillが複数の無関係な目的を持っていないか。単一目的に集中しているか |
| D6 | **フィードバックループ** | 反復タスクに validate → fix → repeat のループと明示的な停止条件があるか |
| D7 | **MCP完全修飾名** | MCPツール参照が完全修飾名（`mcp__server__tool`形式）で記載されているか |
| D8 | **デフォルト付き選択肢** | 選択肢を提示する際にデフォルト（推奨）が明示されているか |

## E. アンチパターン不在確認

| # | アンチパターン | 確認内容 |
|---|--------------|---------|
| E1 | **情報の詰め込み** | SKILL.md に全情報を詰め込んでコンテキストウィンドウを圧迫していないか。Progressive disclosure で分離すべき内容が残っていないか |
| E2 | **曖昧な description** | description が漠然としていて、Skillが適切にトリガーされない恐れがないか |
| E3 | **スコープクリープ** | 1つのSkillに複数の無関係な機能が混在していないか。分割すべきでないか |
| E4 | **ユーザーへの技術的質問** | ユーザーに技術的な判断（APIキーの入力、設定ファイルの編集等）を求めていないか |
| E5 | **環境依存** | 特定のOS・環境に依存する記述（Windowsパス、特定バージョンのツール前提等）がないか |

## F. 本文責務定義

SKILL.md本文に責務・入出力・責任範囲を宣言する6項目（→ [`skill-body-template.md`](./skill-body-template.md)）が含まれ、内容が妥当かを判定する。

### 適用判定基準（先に判定する）

このカテゴリFの適否は、レビュー対象Skillが新規か既存かで変わる。以下を機械的に判定すること:

- 対象の `SKILL.md` が新規作成（未コミット含む）の場合 → **F必須**（F1〜F6を pass、または分類別に明示許可された N/A とする）。新規判定は `git status --porcelain -- <対象SKILL.mdのパス>` の出力先頭が `??`（未追跡）または `A`（ステージ済み新規）かで行う。`git diff --name-status HEAD` は未追跡ファイルを検出しないため使わないこと。
- 既存の `SKILL.md` の変更で、変更目的が「本文責務定義（6項目）の追加・改修」そのもの → **F適用**。
- 上記以外の既存Skillの軽微変更 → **F1〜F6を `N/A（既存・段階移行対象）`** と判定してよい（既存Skillへの6項目の遡及適用は段階移行対象のため）。

| # | チェック項目 | 判定基準 |
|---|------------|---------|
| F1 | **責務** | `## 責務` があり、達成する唯一の主目的が動詞1〜2文で明記されているか。複数責務が接続詞で並んでいないか（並ぶ場合は分割検討の指摘対象） |
| F2 | **スコープ外** | `## スコープ外（やらないこと）` があり、他スキルへ委譲する範囲が**ある場合は**委譲先スキル名つきで明記されているか。委譲先が無い場合は省略可 |
| F3 | **使用タイミング** | `## 使用タイミング` があり、呼び出し元（ユーザー直接／スキル名／サブエージェント名）と局面が明記されているか |
| F4 | **入力** | `## 入力` があり、必須／オプションが「名前・型/形式・説明」で書かれているか。参照型は入力を「なし」または `N/A（参照型のため）` と明記で可 |
| F5 | **出力** | `## 出力` があり、形式（ファイル／パス／文字列／構造化データ等）と内容の骨子が明記されているか。参照型は出力形式を `N/A（参照型のため）` と明記で可 |
| F6 | **依存スキル** | `## 依存スキル` があり、内部で呼ぶ他スキルが列挙、なければ「なし」と明記されているか |
