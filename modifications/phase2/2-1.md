## 実装メモ

### 技術選定
- **バリデーション**: カスタムバリデーション関数（Zodではなく、設計書通りに実装）
- **データベースアクセス**: Prisma Client
- **テストフレームワーク**: Vitest
- **エラーハンドリング**: HTTPステータスコードとエラーメッセージの統一

### 重要な決定事項

#### 1. バリデーション関数
- `validateCreateTodo`: title必須、255文字制限、文字列型チェック
- `validateUpdateTodo`: title/completedのオプション更新、型チェック
- エラーメッセージは要件定義書（requirements.md）の仕様通り
  - "Title is required"
  - "Title cannot be empty"
  - "Title must be 255 characters or less"
  - "Invalid data"

#### 2. APIエンドポイント実装
- **GET /api/todos**: 未完了を上、完了済みを下に並べる（`orderBy: [{ completed: "asc" }, { createdAt: "desc" }]`）
- **POST /api/todos**: バリデーション後、Prismaでレコード作成（201ステータス）
- **PUT /api/todos/:id**: 存在確認後、部分更新（title/completedのみ）
- **DELETE /api/todos/:id**: 存在確認後、削除（204 No Content）

#### 3. エラーハンドリング
- **400 Bad Request**: バリデーションエラー
- **404 Not Found**: "Todo not found"
- **500 Internal Server Error**: "Internal Server Error"

#### 4. テスト戦略
- **ユニットテスト**: バリデーション関数の全ケースをカバー
  - 正常系: 有効なデータ
  - 異常系: title未指定、空文字、255文字超、型不正、completed型不正
- **統合テスト**: Prismaの振る舞いを直接検証
  - CRUD操作の正常系・異常系
  - データベース永続化確認
  - エラーケース（存在しないID）

#### 5. 環境変数設定
- `DATABASE_URL`: PostgreSQL接続文字列（ポート5432）
- `.env.example`と`.env`を両方作成

### 実装時の工夫
1. **設計書との整合性**: 設計書のコードサンプルを参考にしつつ、プロジェクト規約（Biome、タブインデント）に準拠
2. **型安全性**: TypeScriptの型チェックを活用し、unknown型からの適切な型アサーション
3. **テストの網羅性**: バリデーション関数は境界値テストを含む全ケースをカバー
4. **Prismaクライアントの共有**: `lib/prisma.ts`で初期化し、ホットリロード対応
