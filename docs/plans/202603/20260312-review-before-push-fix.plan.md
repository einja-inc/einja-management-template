# レビュー指摘修正 & 完了判定フロー明確化

## Context

前回の実装で、コードレビュー（einja-review-code）を実施する前にコミット・プッシュしてしまった。
CLAUDE.mdの「完了判定の基準」にレビューの必須性は記載されているが、**コミット・プッシュとの実行順序**が明確でなかったため、順序を明記して再発を防止する。
また、レビューで検出された軽微な指摘（末尾改行なし）も修正する。

## 変更内容

### 1. CLAUDE.md「完了判定の基準」セクションの改善

現状:
```
タスク完了を宣言する前に、以下を必ず検証する。
（レビュー → 必須チェック → 禁止事項 の順で記載）
```

変更後: **実行順序を明示的なフロー**として記載し、「レビュー・検証がすべて完了してからコミット・プッシュ」を厳守事項として追加。

```
### 完了判定フロー（厳守）

1. `einja-review-code` Skill でレビュー実施（スキップ条件に該当しない場合）
2. MAJOR指摘があればユーザーに報告・修正
3. 必須チェック実施（ディスク確認、prepush、動作確認、git diff）
4. すべて合格後、コミット・プッシュ（`einja-task-commit` Skill）

**【厳守】レビュー・検証が完了するまでコミット・プッシュは禁止。**
```
