  - エラー発生箇所（ファイルパス）を明示
  - エラー詳細（OS提供のエラーメッセージ）を含める

**実装例**:
```typescript
try {
  // コピー先ディレクトリを作成
  const destDir = dirname(destinationPath);
  if (!existsSync(destDir)) {
    mkdirSync(destDir, { recursive: true });
  }

  // ファイルコピー
  copyFileSync(sourceFile.absolutePath, destinationPath);
} catch (error) {
  // ファイル書き込みエラーの詳細を提供
  const errorMessage = error instanceof Error ? error.message : String(error);
  throw new Error(
    `ファイルの書き込みに失敗しました: ${destinationPath}\n詳細: ${errorMessage}`
  );
}
```

**受け入れ基準の達成状況**:
- ✅ AC10.7: ファイル書き込みエラー時に詳細なエラーメッセージが表示される

## 実装メモ

### JSON出力時の標準出力/標準エラー出力の分離

**設計原則**:
- JSON出力時は標準出力にJSONのみを出力
- 進捗ログは標準エラー出力に出力
- 通常モード時は標準出力にすべて出力

**実装のポイント**:
- `const log = options.json ? console.error : console.log;`で出力先を切り替え
- JSON出力関数(`printJsonOutput()`)は常に標準出力を使用
- エラー出力関数(`printError()`)はJSON形式でも標準出力を使用（JSONレスポンスとして）

### ファイル書き込みエラーハンドリング

**設計原則**:
- エラー発生箇所（ファイルパス）を明示
- OS提供のエラーメッセージを保持
- エラーの連鎖を適切に処理

**実装のポイント**:
- try-catch内でファイル書き込みエラーをキャッチ
- 詳細なエラーメッセージを含む新しいErrorをスロー
- 既に詳細情報を含むエラーはそのまま再スロー

### TypeScript型安全性

- any型の使用なし
- 全てのエラーハンドリングで型ガードを使用
- インターフェース定義に準拠した実装
