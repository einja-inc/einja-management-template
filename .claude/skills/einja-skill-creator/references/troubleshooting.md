# Skillトラブルシューティングガイド

Skillの一般的な問題と対処法。

## トリガー問題

### Undertriggering（トリガーされない）

**シグナル**:
- 適切なクエリでSkillが呼び出されない
- ユーザーが明示的にSkill名を指定しないと動作しない

**対策**:
1. **descriptionを具体的にする**: 抽象的な表現を具体的なユースケースに置き換える
2. **トリガーキーワードを増やす**: ユーザーが使いそうな表現を複数含める
3. **ファイルタイプを明記する**: `.pdf`, `.docx`等の拡張子をdescriptionに含める
4. **descriptionを少し「積極的」にする**: Claudeはアンダートリガーしやすいため

**例**:
```
# Before（トリガーされにくい）
description: ドキュメントを処理する

# After（トリガーされやすい）
description: PDFファイルの読み取り・作成・編集・変換を行う。.pdfファイルの操作、フォーム入力、ページ分割・結合、テキスト抽出が必要な場合に使用。
```

### Overtriggering（過剰トリガー）

**シグナル**:
- 無関係なクエリでSkillが呼び出される
- 類似Skillと混同される

**対策**:
1. **ネガティブトリガーを追加**: `Do NOT use for: [除外シーン]（→ 代替skill）`
2. **descriptionを絞り込む**: 広すぎる表現を具体的に限定
3. **類似Skillとの境界を明確化**: 何が違うかを明示

## 指示遵守の問題

### 指示が守られない

**シグナル**:
- 出力フォーマットが指定と異なる
- 特定のステップがスキップされる

**対策**:
1. **理由を説明する**: 「なぜ」この形式が必要かを記述する（MUST/ALWAYS連発の代わりに）
2. **具体例を追加する**: 期待される入力→出力の例を含める
3. **出力テンプレートを提供する**: 具体的なテンプレートをSkillに含める
4. **指示をシンプルにする**: 複雑すぎる指示は分割・簡略化する

### 出力品質が不安定

**シグナル**:
- 同じプロンプトで異なる品質の結果が返る
- 特定のケースでのみ品質が低下する

**対策**:
1. **エッジケースに対応する**: 問題が発生するパターンを特定し、条件分岐で対処
2. **デフォルト動作を明示する**: 曖昧な状況でどう振る舞うべきかを記述
3. **テストケースを追加する**: 品質低下パターンをテストに含める

## コンテキストの問題

### コンテキストが大きすぎる

**シグナル**:
- SKILL.md本文が500行を超えている
- モデルの応答が遅い・不正確

**対策**:
1. **段階的開示を活用する**:
   - L1: Frontmatter（~100語）— 常に読み込み
   - L2: SKILL.md本文（500行以内）— トリガー時に読み込み
   - L3: references/（無制限）— 必要に応じて読み込み
2. **references/に分割する**: ドメイン別・機能別にファイルを分ける
3. **SKILL.mdから明確に参照する**: いつどのreferenceを読むべきか記載
4. **大きなreferenceファイル（300行超）には目次を含める**

### スクリプトの重複作業

**シグナル**:
- テスト実行でサブエージェントが毎回同じヘルパースクリプトを書く

**対策**:
- scripts/にヘルパースクリプトをバンドルする
- SKILL.mdからスクリプトの存在と使い方を明示する

## Description最適化ループの問題

### 最適化が収束しない

**対策**:
1. 評価クエリセットを見直す（現実的でないクエリを除外）
2. trainとtestの分割比率を調整する
3. 最大イテレーション数を増やす（デフォルト5回）

### トリガー率が向上しない

**対策**:
1. descriptionだけでなくSkill名も見直す
2. 類似Skillとの競合を確認する
3. 評価クエリが十分に多様か確認する（エッジケース重視）
