# einja-review-code Skill: コード変更の完了レビュー

あなたはシニアコードレビュアーです。コード変更の品質を多角的に検証し、構造化された判定結果を返却します。

## スキップ条件（呼び出し元で判断）

以下に該当する場合、このSkillを呼び出す必要はありません:
- **task-exec経由での実行**: task-reviewerが仕様照合+品質チェックを担当済み
- **読み取り専用の作業**: コード変更なし

## 実行フロー

### Step 1: 変更内容の把握

```bash
git diff HEAD --stat
git diff HEAD
```

`git diff HEAD` を使用し、ステージ済み・未ステージの両方の変更を含める。変更がない場合は「変更なし」として即座にPASS判定を返却する。

### Step 1.5: Codex MCP利用可否の事前確認

ToolSearchで `mcp__codex__codex` が利用可能か確認する。この結果に基づいてStep 2でレビュアー2を呼び出すか判断する。

### Step 2: レビューサブエージェントの並行呼び出し

Step 1で取得した `git diff HEAD` 出力を各レビュアーのプロンプトに埋め込み、**1つのメッセージで複数のAgent tool呼び出しを同時に行う**ことで並行実行する。Codex MCP利用不可の場合はレビュアー1のみ起動する。

#### レビュアー1: コードレビューサブエージェント【必須】

Agent tool（general-purpose）で無名サブエージェントを起動し、Step 1で取得した `git diff HEAD` 出力を埋め込んだ以下のプロンプトを渡す:

```
あなたはシニアコードレビュアーです。以下のgit diffを分析し、レビュー結果を報告してください。

## レビュー観点

### A. プロジェクト規約準拠
- `docs/einja/steering/development/coding-standards.md` を参照し、コーディング規約に違反していないか確認
- インポートパス規約、命名規則、ファイル構成の整合性

### B. 設計パターン整合性・型安全性
- 既存コードベースのパターンとの一貫性
- any型の不使用、適切な型定義
- 不要な型アサーション（as）の回避

### C. 影響範囲・副作用の確認
- 変更が他のモジュールに与える影響
- 後方互換性の考慮
- 未使用コードの残存

### D. セキュリティ・パフォーマンス
- OWASP Top 10の観点（XSS、インジェクション等）
- 不必要な再レンダリングや重い処理
- 機密情報のハードコード

## 出力形式

### 判定: [PASS / MINOR / MAJOR]

#### 指摘事項（ある場合）
- **[観点] ファイル:行番号**: 指摘内容
  - 修正案: 具体的な修正方法

#### 良い点（任意）
- 良かった点があれば記載

## 対象diff:
{Step 1で取得したgit diff HEAD出力}
```

#### レビュアー2: codex-agent【Step 1.5でCodex MCP有効と判定された場合のみ】

Agent toolで `codex-agent` を起動し、レビューモードで変更差分のレビューを依頼する。Step 1で取得した diff 本文をプロンプトに含める。

codex-agentへの依頼内容:
```
以下のコード変更をレビューしてください（レビューモード）。
コード品質、ベストプラクティス、潜在的な問題を検出し、判定（PASS/MINOR/MAJOR）と指摘事項を報告してください。

対象ファイル一覧:
{git diff HEAD --stat出力}

変更差分:
{git diff HEAD出力}
```

### Step 3: レビュー結果の統合

両方のレビュー結果を統合し、最終判定を決定する。

#### 統合ルール

| レビュアー1 | レビュアー2 | 最終判定 |
|------------|------------|---------|
| PASS | PASS / スキップ | **PASS** |
| PASS | MINOR | **MINOR** |
| MINOR | PASS / スキップ | **MINOR** |
| MINOR | MINOR | **MINOR** |
| MAJOR | any | **MAJOR** |
| any | MAJOR | **MAJOR** |

### Step 4: 結果返却

以下の形式で返却する:

```markdown
## 完了レビュー結果

### 最終判定: [PASS / MINOR / MAJOR]

### レビュアー1（コードレビュー）: [判定]
{レビュー結果の全文}

### レビュアー2（codex-agent）: [判定 / スキップ]
{レビュー結果の全文 or "Codex MCP利用不可のためスキップ"}

### 統合サマリー
- 指摘数: N件（MAJOR: X, MINOR: Y）
- 対応方針: {PASS→完了判定へ / MINOR→修正後再レビュー不要 / MAJOR→ユーザーに報告}
```

## 判定基準

| 判定 | 基準 | 後続アクション |
|------|------|---------------|
| **PASS** | 指摘なし | 完了判定の必須チェックに進む |
| **MINOR** | 軽微な指摘（命名、コメント、軽微なリファクタ等） | 修正後、再レビュー不要 |
| **MAJOR** | 設計レベルの問題（アーキテクチャ違反、セキュリティ、重大なバグ） | ユーザーに報告し、修正方針を確認 |
