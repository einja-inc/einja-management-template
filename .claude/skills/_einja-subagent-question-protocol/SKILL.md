# サブエージェント質問プロトコル（PENDING_QUESTIONS）

## 背景

Claude Code v2.0.56以降、**サブエージェントではAskUserQuestionツールがシステムレベルでフィルタリングされ動作しない**。
そのため、サブエージェントがユーザーへの確認が必要な場合は、以下のプロトコルに従って質問を返却する。

## プロトコル概要

1. サブエージェントは質問を `## PENDING_QUESTIONS` セクションとして出力に含める
2. 親エージェントが出力を検出し、調査可能な質問は自律解決を試み、判断必須の質問はAskUserQuestionでユーザーに確認する
3. 親エージェントがAgent toolの `resume` パラメータで同じサブエージェントを再開する
4. 再開時に回答（自律解決分＋ユーザー確認分）がプロンプトとして渡される

## PENDING_QUESTIONS フォーマット

質問を返却する場合、**必ず以下の形式**で出力し、その後停止すること：

```markdown
## PENDING_QUESTIONS

以下の不明点の解消が必要です。

### Q1: [質問タイトル]
**背景**: [なぜこの質問が必要か、どのような文脈で発生したか]
**タイプ**: `researchable` | `decision-required`

| 選択肢 | 説明 | メリット | デメリット |
|--------|------|----------|------------|
| A: [ラベル] | [詳細説明] | [メリット] | [デメリット] |
| B: [ラベル] | [詳細説明] | [メリット] | [デメリット] |
| C: [ラベル] | [詳細説明] | [メリット] | [デメリット] |

**推奨**: A（[推奨理由]）

### Q2: [質問タイトル]
**背景**: [なぜこの質問が必要か]
**タイプ**: `researchable` | `decision-required`

| 選択肢 | 説明 | メリット | デメリット |
|--------|------|----------|------------|
| A: [ラベル] | [詳細説明] | [メリット] | [デメリット] |
| B: [ラベル] | [詳細説明] | [メリット] | [デメリット] |

**推奨**: B（[推奨理由]）
```

## ルール

1. **1回にまとめる**: 複数の質問がある場合は Q1, Q2, ... としてまとめて返却する。1問ずつ返却しない
2. **選択肢と背景を必ず含める**: 各選択肢には説明・メリット・デメリットを記載し、ユーザーが十分な情報に基づいて判断できるようにする
3. **推奨を明示する**: 各質問に対して推奨選択肢とその理由を記載する
4. **タイプを付与する（推奨）**: 各質問に `**タイプ**` フィールドを付与し、親エージェントの処理を効率化する
   - `researchable`: 技術的事実・ベストプラクティスで客観的に答えられる（例: ライブラリ比較、API仕様、パフォーマンス特性）
   - `decision-required`: ビジネス要件・ユーザー意図・スコープ決定が必要（例: 機能スコープ、優先度、デザイン解釈）
   - タイプは任意フィールド（省略時は親エージェントが自動判定する）
5. **質問返却後は停止する**: PENDING_QUESTIONSを出力したら、それ以降の作業は行わない。回答を受けてから再開する
6. **再開後の作業継続**: `resume` で再開された場合、渡された回答に基づいて作業を継続する

## AskUserQuestion YAML → PENDING_QUESTIONS 変換ガイド

エージェント定義にAskUserQuestion YAMLの参考例がある場合、以下のように変換する：

### 変換前（AskUserQuestion YAML）
```yaml
AskUserQuestion:
  question: "状態管理ライブラリを選択してください"
  header: "状態管理"
  options:
    - label: "TanStack Query（推奨）"
      description: "推奨理由: サーバー状態管理に最適。..."
    - label: "Zustand"
      description: "シンプルなグローバル状態管理。..."
```

### 変換後（PENDING_QUESTIONS形式）
```markdown
## PENDING_QUESTIONS

以下の不明点の解消が必要です。

### Q1: 状態管理ライブラリの選択
**背景**: サーバー状態の管理方式を決定する必要があります。

| 選択肢 | 説明 | メリット | デメリット |
|--------|------|----------|------------|
| A: TanStack Query | サーバー状態管理に最適 | 自動キャッシュ管理、型安全 | 学習コスト中程度 |
| B: Zustand | シンプルなグローバル状態管理 | 軽量、シンプルなAPI | サーバー状態管理は手動 |

**推奨**: A（サーバー状態管理に最適で、キャッシュと再取得が自動化されるため）
```

## 親エージェント処理フロー（PENDING_QUESTIONS受信時）

親エージェントがPENDING_QUESTIONSを受信した場合、以下のフローで処理する:

### 1. 質問の分類

各質問を以下のカテゴリに分類する:

| カテゴリ | 判定基準 | 対応 |
|---------|---------|------|
| **調査可能（researchable）** | 技術的事実・ベストプラクティスで客観的に答えられる | 自律解決を試みる |
| **判断必須（decision-required）** | ビジネス要件・ユーザー意図・スコープ決定が必要 | ユーザーにエスカレーション |

- `**タイプ**` フィールドがある場合はそれを参考にする（最終判断は親エージェント）
- `**タイプ**` フィールドがない場合は親エージェントが自動判定する
- **迷った場合は「判断必須」**（安全側に倒す）

### 2. 調査可能な質問の自律解決

以下の順序で解決を試みる:
1. **自身のコンテキスト**: steering docs、memory、プロジェクト知識
2. **Web検索**: WebSearch/WebFetchで技術的事実を調査
3. **Codex相談**: codex-agentに技術的な相談を行う

### 3. ユーザーへの報告

**自律解決した場合もサイレントに進めず、必ずユーザーに報告する。**

- **自律解決した質問**: 根拠を付けて報告する（ユーザーが異議あれば上書き可能）
- **未解決/判断必須の質問**: AskUserQuestionで確認する

### 4. サブエージェントの再開

全回答が揃ったら、Agent toolの `resume` パラメータで同じサブエージェントを再開し、回答を含めて渡す。

## 重要な注意事項

- このプロトコルは**サブエージェントとして動作する場合にのみ**適用される
- 親エージェント（直接ユーザーと対話する場合）では通常通りAskUserQuestionを使用すること
- エージェント定義内のAskUserQuestion YAMLは「どんな質問をすべきか」の参照情報として有用なので削除しない
