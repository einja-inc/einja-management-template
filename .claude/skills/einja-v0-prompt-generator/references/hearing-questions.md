## 2. Q1: 機能概要・目的

**目的**: 生成する画面が「誰に対して」「何を達成するか」を1〜3文で把握する。プロンプトの `Purpose` セクションと `{feature_name}` slug 生成に使用。

**形式**: 単一選択（テンプレート例5つ + 自由入力）。テンプレートを選ぶと定型文が入力欄に補完される想定。

**質問文と選択肢**:
```
質問: "作りたい画面の機能概要・目的を1〜3文で教えてください（誰が使う、何をする画面か）"
ヘッダー: "機能概要（Q1）"
選択肢:
  - A: Dashboard 例
    description: 例）「倉庫管理者が在庫レベルを監視し、低在庫アラートを検知するダッシュボード」
    Note: KPI + テーブル型ダッシュボード想定。アクター（誰が使う）+ ゴール（何を達成）の構造を踏襲すると v0 が意図を汲みやすい
  - B: Form 例
    description: 例）「サービス利用者が新規アカウントを登録する、SNS連携対応のサインアップフォーム」
    Note: 入力フォーム系の雛形。バリデーション・SSOの有無まで含めると精度向上
  - C: Landing 例
    description: 例）「B2B SaaS の見込み顧客向け、Hero + 特徴3つ + CTAのランディングページ」
    Note: マーケティング系画面の雛形。訴求ポイント数とCTA導線を含めると v0 が構造化しやすい
  - D: List 例
    description: 例）「営業担当が顧客一覧を検索・フィルタし詳細画面へ遷移するリスト画面」
    Note: 検索・フィルタ・詳細遷移まで含めるとテーブル/カード判断が精緻に
  - E: その他（自由入力）
    description: 上記テンプレートに該当しない機能概要・目的を自由記述する
    Note: 誰が使うか（アクター）と何を達成するか（ゴール）を含めると v0 が意図を汲みやすい。日本語のままで可
```

**バリデーション**: A〜D選択後は「このまま使う/微修正」の2択を出し、修正時は自由入力で上書き。Eは自由入力必須（空文字時は再質問）

## 3. Q2: 画面種別

**目的**: 生成する画面のカテゴリを1つ決定する。Q3 の推奨要素セット、プロンプト冒頭 `Build a {Q2} for ...` の埋め込み値に使用。

**形式**: 単一選択

**質問文と選択肢**:
```
質問: "生成する画面の種別を1つ選択してください"
ヘッダー: "画面種別（Q2）"
選択肢:
  - A: Landing
    description: 製品/サービス紹介のトップページ・ランディングページ
    Note: Hero, CTA, 特徴セクション, フッターが定番構成。マーケティング向けで訴求力重視。認証や複雑な操作はスコープ外
  - B: Dashboard
    description: 指標・データを一覧するダッシュボード画面
    Note: サイドバー + KPIカード + テーブル/チャートが定番。B2B/管理画面向け。データ密度と情報階層が重要
  - C: Form
    description: フォーム入力画面（登録・編集・設定等）
    Note: ラベル + 入力 + バリデーション + 送信ボタンが定番。単一目的の入力タスクに最適。マルチステップの場合はウィザードとして扱う
  - D: List
    description: 一覧画面（テーブル/カードグリッド/リスト）
    Note: 検索・フィルタ・ソート・ページネーションが定番。データ探索・選択ユースケース向け
  - E: Chat
    description: チャット/メッセージング画面
    Note: メッセージバブル + 入力欄 + 送信 + スレッド表示が定番。AI/カスタマーサポート/メッセージ機能向け
  - F: Auth
    description: 認証画面（ログイン・サインアップ・パスワード再設定）
    Note: 中央寄せカード + フォーム + SSOボタンが定番。バリデーションとエラーメッセージの視認性が重要
  - G: その他（自由入力）
    description: 上記に該当しない画面種別を自由記述する
    Note: 例: 「設定画面」「詳細画面」「ウィザード」「カレンダー」等。自由入力した内容がプロンプト冒頭に埋め込まれる
```

**バリデーション**: 単一選択のため必ず1つ選択される

## 4. Q3: 主要画面要素

**目的**: 画面に配置する UI 要素を複数選択で決定する。`### Layout & Content Areas` セクションの箇条書きに変換される。

**形式**: 複数選択（スキップ可）

**質問文と選択肢**:
```
質問: "画面に含める主要要素を選択してください（複数可、スキップ可）"
ヘッダー: "主要画面要素（Q3）"
選択肢:
  - A: Header
    description: 上部ヘッダー（ロゴ・ナビ・ユーザーメニュー等）
    Note: ほぼ全画面で使う定番要素。Landing/Dashboard/Auth で推奨
  - B: Sidebar
    description: 左サイドバー（ナビゲーション・セクション分け）
    Note: Dashboard/List で推奨。240px 前後の幅が一般的
  - C: Footer
    description: フッター（法的リンク・二次ナビ）
    Note: Landing で推奨。Dashboard では省略されることも多い
  - D: KPI
    description: KPI/メトリックカード（値・ラベル・増減）
    Note: Dashboard で推奨。3〜4枚の並びが視認性良好
  - E: Table
    description: データテーブル（ソート・ページネーション対応）
    Note: Dashboard/List で推奨。列数と行密度に注意
  - F: Chart
    description: グラフ・チャート（棒/線/円等）
    Note: Dashboard で推奨。データ形状に応じて種類を v0 が自動選択
  - G: Form
    description: フォーム（入力・バリデーション・送信ボタン）
    Note: Form/Auth で推奨。ラベル位置とエラー表示に配慮
  - H: Modal
    description: モーダル・ダイアログ（確認・集中編集用）
    Note: Dashboard/List で補助的に使用。破壊的操作の確認等
  - I: Toast
    description: トースト通知（非同期処理結果の一時表示）
    Note: 操作フィードバックが必要な画面で推奨
  - J: Wizard
    description: 複数ステップウィザード（プログレスインジケータ付き）
    Note: 長いフォームや初期セットアップに最適
  - K: Search
    description: 検索入力（クリアボタン付き、結果リスト表示）
    Note: List/Dashboard で推奨。オートコンプリート等の追加動作は Q6 で指示
  - L: スキップする
    description: このQを飛ばす（Layout セクションはデフォルト "Use shadcn/ui default layout patterns." に置換）
    Note: v0 に一任したい場合。プロンプトの具体性が下がる代わりに v0 の自由度が上がる ※ 他の要素と併選できません（排他選択）
  - M: その他（自由入力）
    description: 上記以外の要素を自由記述する
    Note: 例: 「ステッパー」「タブナビゲーション」「カレンダーピッカー」等
```

**Q2 分岐に応じた推奨マーク:**
- Q2=Landing → A/C/M 推奨（Header, Footer, Hero相当を自由入力）
- Q2=Auth → G 推奨（Form 中心、Sidebar/Footer は不要）
- Q2=Dashboard → B/D/E/F 推奨
- Q2=Form → G/J 推奨
- Q2=List → E/K 推奨
- Q2=Chat → 独自（メッセージ入力欄等）→ M 推奨

**バリデーション**: 複数選択可、`L: スキップする` が排他（他と併選できない）

## 5. Q4: 状態・インタラクション

**目的**: 状態遷移や特殊なインタラクションを複数選択で指定。`### States & Interactions` セクションに変換される。

**形式**: 複数選択（スキップ可）

**質問文と選択肢**:
```
質問: "考慮したい状態・インタラクションを選択してください（複数可、スキップ可）"
ヘッダー: "状態・インタラクション（Q4）"
選択肢:
  - A: Loading
    description: ローディング状態（スケルトン・スピナー）
    Note: データ取得中の視覚フィードバック。ほぼ全画面で有用
  - B: Empty
    description: 空状態（データが0件の時の表示）
    Note: List/Dashboard で必須。イラスト + 説明 + 次アクション導線が定番
  - C: Error
    description: エラー状態（データ取得失敗・処理失敗）
    Note: リトライボタン + エラーメッセージが定番。ユーザーの次アクションを明示
  - D: Success
    description: 成功状態（送信完了・保存完了等）
    Note: Toast + アイコンで一時表示、または完了画面への遷移
  - E: Hover
    description: ホバー効果（カード・ボタン等）
    Note: インタラクティブ要素の可視性向上。過度なアニメーションは避ける
  - F: Validation
    description: フォームバリデーション（インライン表示）
    Note: Form/Auth で必須。エラーメッセージは入力直下、色は赤系
  - G: Responsive
    description: レスポンシブ対応（mobile-first, sm/md/lg breakpoints）
    Note: プロンプトに "Responsive breakpoints (mobile-first, sm/md/lg)" を自動追加。モバイル対応が必要なら必ず選択
  - H: Dark Mode
    description: ダークモード対応（トグル or システム設定連動）
    Note: プロンプトに "Include a dark mode toggle in the header" を自動追加。カラーコントラストにも影響
  - I: なし
    description: 特別な状態指定なし（v0 デフォルトに一任）
    Note: 静的モックで十分な場合。States セクションはプロンプトから削除される ※ 他の状態と併選できません（排他選択）
  - J: その他（自由入力）
    description: 上記以外の状態・インタラクションを自由記述する
    Note: 例: 「無限スクロール」「ドラッグ&ドロップ」「オートセーブ表示」等
```

**分岐ロジック（プロンプト自動追加）:**
- G=Responsive 選択時 → `### States & Interactions` に `- Responsive breakpoints (mobile-first, sm/md/lg)` を必ず追加
- H=Dark Mode 選択時 → `### States & Interactions` に `- Include a dark mode toggle in the header` を必ず追加

**バリデーション**: 複数選択可、`I: なし` は排他

## 6. Q5: スタイル志向

**目的**: 全体のビジュアルトーンを1つ決定。`### Visual Style` セクションに変換される。

**形式**: 単一選択

**質問文と選択肢**:
```
質問: "全体のスタイル志向を1つ選択してください"
ヘッダー: "スタイル志向（Q5）"
選択肢:
  - A: Modern
    description: モダン・ミニマル、余白多め、繊細なシャドウ、角丸
    Note: 汎用性が高くほぼ全ジャンルに合う。デフォルト推奨候補
  - B: Enterprise
    description: エンタープライズ、密度高め、ニュートラルグレー + 1つのアクセントカラー
    Note: B2B/管理画面向け。情報密度を重視、装飾を最小限に
  - C: Playful
    description: ポップ・鮮やかなパレット、角丸、フレンドリーなタイポグラフィ
    Note: コンシューマ向けサービス、教育、エンタメ系に最適
  - D: Minimal
    description: ミニマル・モノクロ、グラデーションなし、タイポグラフィと余白重視
    Note: ポートフォリオ・ドキュメント系に最適。カラーで訴求したい場合は不向き
  - E: Dark
    description: ダークテーマ基調、高コントラスト、暗背景に色付きアクセント
    Note: 開発者ツール・音楽/動画系サービスに最適。Q4 のダークモード選択と併用可
  - F: その他（自由入力）
    description: 上記以外のスタイル志向を自由記述する
    Note: 例: 「ブルータリズム」「ネオモルフィズム」「グラスモーフィズム」「和風モダン」等。v0 が解釈できる粒度で書くと精度向上
```

**バリデーション**: 単一選択のため必ず1つ選択される

## 7. Q6: 追加指示

**目的**: 上記Q1〜Q5で拾いきれない v0 固有の指示・特殊要件を自由入力。`### Additional Requirements` セクションに変換される。

**形式**: 自由入力（スキップ可）

**質問文と選択肢**:
```
質問: "追加で v0 に伝えたい指示があれば入力してください（スキップ可）"
ヘッダー: "追加指示（Q6）"
選択肢:
  - A: スキップする
    description: 追加指示なし（プロンプトから Additional Requirements セクションを削除）
    Note: Q1〜Q5 で十分な場合。生成 .md がシンプルになる
  - B: その他（自由入力）
    description: 追加指示を自由記述する
    Note: 例）「Sign in with Google ボタンを含める」「言語切替ドロップダウンをヘッダー右上に配置」「shadcn/uiのCommand コンポーネントで検索を実装」等
```

**バリデーション**: 空文字入力 → A スキップと同扱い

## 8. 分岐ロジック集約

| 分岐条件 | 動作 | 実装Step |
|---|---|---|
| Q2=Landing | Q3 で Header/Footer/M（自由入力）を推奨マークで強調 | Step 2 |
| Q2=Auth | Q3 で Form を推奨マークで強調、Sidebar/Footer を非推奨マーク | Step 2 |
| Q2=Dashboard | Q3 で Sidebar/KPI/Table/Chart を推奨マークで強調 | Step 2 |
| Q3=L（スキップ） | `### Layout & Content Areas` を "Use shadcn/ui default layout patterns." に置換 | Step 3 |
| Q4=G（Responsive） | `### States & Interactions` に breakpoints 行を自動追加 | Step 3 |
| Q4=H（Dark Mode） | `### States & Interactions` に dark mode toggle 行を自動追加 | Step 3 |
| Q4 空配列 or I=なし | `### States & Interactions` セクションごと削除 | Step 3 |
| Q6=A（スキップ）or 空欄 | `### Additional Requirements` セクションごと削除 | Step 3 |

**推奨マーク実装ヒント**: AskUserQuestion 自体には視覚強調機能がないため、`description` 冒頭に `[推奨]` プレフィックスを付ける、または `Note:` 末尾に `※ Q2={value} で推奨` を追記する形で表現する。

## 9. 選択肢共通ルール

すべての AskUserQuestion 呼び出しで以下を厳守:

1. **2層記述**: 各選択肢に `description`（What）と `Note:`（So What: メリット/デメリット/注意点）を必ず含める
2. **「その他（自由入力）」必須**: 全質問の選択肢末尾に「その他（自由入力）」を明示配置（AskUserQuestion 自動提供の "Other" に加えて）
3. **排他選択肢の明示**: `スキップする`/`なし` は Note に「他と併選できません」を明記
4. **選択肢数**: 単一選択5〜7個、複数選択10個以内を目安（Q3のように要素多次元の質問は12-13個まで許容）。超過時は Q6 自由入力に誘導
5. **推奨マーク**: `Note:` 末尾に `※ 推奨` または `※ Q2={value} で推奨` を追記
