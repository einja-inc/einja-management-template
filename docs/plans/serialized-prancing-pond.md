# 実装フェーズに完了検証タスク（99系）を追加

## Context

現状の実装フェーズはステップ4が「実装→検証」を1行で済ませており、コードレビュー・動作確認が完了する前にコミット・プッシュされることを防ぐ明示的な順序制約がない。準備ステップ（0-1, 0-2, 0-3）と同様に、完了検証をTaskAPIの固定タスク（99系）として必ず作成させることで、スキップ不可能な検証ゲートを設ける。

## 変更内容

**対象**: `CLAUDE.md` 99-103行目（実装フェーズ）

### 現状

```markdown
1. **タスク0**: Planファイルを `docs/plans/YYYYMM/YYYYMMDD-機能名.plan.md` にリネーム
2. **Skill作成**（TODO-0がある場合）
3. **worktree作成**: `_einja-worktree-guide` Skillに従い、EnterWorktree → セットアップ → 作業開始
   - 例外（worktree不要）: ドキュメントのみ、設定のみ、1ファイル30行未満の軽微修正
4. Task API で進捗管理しながら実装。完了時は「完了判定の基準」に従って検証
```

### 変更後

```markdown
1. **タスク0**: Planファイルを `docs/plans/YYYYMM/YYYYMMDD-機能名.plan.md` にリネーム
2. **Skill作成**（TODO-0がある場合）
3. **worktree作成**: `_einja-worktree-guide` Skillに従い、EnterWorktree → セットアップ → 作業開始
   - 例外（worktree不要）: ドキュメントのみ、設定のみ、1ファイル30行未満の軽微修正
4. Task API で進捗管理しながら実装
5. **完了検証タスク（99系）**: 全実装タスク完了後、以下をTaskCreateで作成し順次実行する。**全タスクが完了するまでコミット・プッシュ禁止**

| タスクID | 内容 | 実行方法 |
|---------|------|---------|
| 99-1 | コードレビュー | `einja-review-code`（MAJOR → 修正→再レビュー）。差分確認（`git diff --stat`）もここで実施 |
| 99-2 | 動作確認 | API→curl、画面→Playwright MCP、スクリプト→実行確認 |
| 99-3 | コミット・プッシュ | `einja-task-commit` で実行（内部で `pnpm prepush` を実行） |
```

### ポイント
- 99系は固定テンプレート。Planのタスク一覧には記載不要（実装フェーズで自動作成）
- 99-3（コミット・プッシュ）は99-1〜99-2がすべてcompletedになるまで開始しない
- `pnpm prepush`（lint + typecheck + test）は `einja-task-commit` 内のStep 4で実行されるため独立タスク不要
- `git diff --stat` は `einja-review-code` のStep 1で実施されるため独立タスク不要
- 「完了判定の基準」セクションは99系と重複するため、99系への参照に簡略化

### 「完了判定の基準」セクション（247-266行目）の変更

現状の必須チェックリストは99系タスクと重複するため、簡略化:

```markdown
## 完了判定の基準

実装フェーズの **99系タスク**（完了検証）をすべて実行・通過すること。

- task-exec経由の場合: task-reviewerが品質チェック担当済みのため、99-1（コードレビュー）はスキップ可
- 読み取り専用の作業: 99系タスク自体が不要
```
