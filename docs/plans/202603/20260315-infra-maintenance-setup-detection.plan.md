# Plan: einja-infra-maintenance の初期セットアップ検出ロジック改善

## Context

`einja-infra-maintenance` を引数なしで呼び出した際、`.env.keys` は存在するが `.env.personal` が未作成、環境別ファイルが一部欠損しているなど「一度もセットアップを完了していない」兆候がある場合でも、Phase 2 メインメニューに「環境セットアップ（フルセットアップ）」が推奨表示されない。

## 現状

### Phase 0 の検出範囲が狭い
- `.env.keys` 不在 → フルセットアップ提案
- `.env.keys` 存在 + 環境別ファイル不在 → 環境別ファイル作成提案
- **上記以外はスルー** → `.env.personal` 不在、Docker未起動等は検出しない

### Phase 2 推奨ロジックの「フルセットアップ」条件が限定的
- `.env.keys` 不在時のみ「環境セットアップ（フルセットアップ）」を推奨
- `.env.personal` 不在 → 「環境変数管理」が推奨されるが、フルセットアップは推奨されない

### 結果
初回セットアップが途中で止まっている状態（`.env.keys` はあるが他が未完了）で、ユーザーがフルセットアップの存在に気づけない。

## 変更内容

### 対象ファイル
- `.claude/skills/einja-infra-maintenance/SKILL.md`

### 修正方針: Phase 2 推奨ロジックの拡張

Phase 2 の推奨ロジックに「初回セットアップ未完了」の複合条件を追加する。

**追加する推奨条件:**

| 検出結果 | 推奨カテゴリ |
|---------|------------|
| `.env.keys`不在 | 環境セットアップ（フルセットアップ）← 既存 |
| **環境別ファイル（develop/staging/production/preview）のいずれか不在** | **環境セットアップ（フルセットアップ）** ← 新規 |
| **`.env.personal`不在** | **環境セットアップ（フルセットアップ）** ← 新規 |
| **❌が3個以上検出（Phase 1結果）** | **環境セットアップ（フルセットアップ）** ← 新規（既存の「デプロイ検査」推奨と併記） |

これにより：
- 環境別ファイルが揃っていない → フルセットアップ推奨
- `.env.personal` が未作成 → フルセットアップ推奨
- Phase 1 で多数の❌が検出された → フルセットアップ推奨

Phase 0 のフローは変更しない（Phase 0 は AskUserQuestion で即座に提案するフローなので、役割が異なる）。
