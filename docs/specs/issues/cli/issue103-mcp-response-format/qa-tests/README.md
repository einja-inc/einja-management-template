# QAテスト結果ディレクトリ構造

## 概要
このディレクトリは、Issue #103（vibe-kanban MCP start_workspace_session レスポンス形式変更対応）のタスク実装後のQAテスト結果を記録するためのものです。

## ディレクトリ構造
```
qa-tests/
├── README.md       # このファイル（QAテストガイド）
├── scenarios.md    # シナリオテスト仕様（必須）
├── phase1/         # フェーズ1のテスト
│   ├── 1-1.md     # タスク1.1のテスト結果（MCPレスポンス形式の調査）
│   ├── 1-2.md     # タスク1.2のテスト結果（型定義の更新）
│   ├── 1-3.md     # タスク1.3のテスト結果（パース処理の修正）
│   ├── 1-4.md     # タスク1.4のテスト結果（テストの更新と動作確認）
│   └── evidence/   # スクリーンショット等のエビデンス
└── summary.md      # 全体のテストサマリー（オプション）
```

## QAテストファイルの記載内容

各QAテストファイル（例：`phase1/1-1.md`）には以下を記載：

1. **ヘッダー情報**: テスト対象タスク、実装日、テスト実施日
2. **各タスクのテスト内容**: 受け入れ条件（AC番号）、テストシナリオ（表形式）、全体ステータス、主な問題点、対応策、エビデンス
3. **統合テスト結果サマリー**: フェーズ全体の結果サマリー、次フェーズへの引き継ぎ事項、改善提案

## テスト結果の更新方針

- **上書き更新**: 実施結果セクションは最新の結果のみを記載。過去の履歴は保持しない（Gitで管理）。更新日時を必ず記載。
- **ステータス定義**: ✅ PASS（すべての受け入れ条件を満たす）、❌ FAIL（要修正）、⚠️ PARTIAL（軽微な問題あり）、🔄 未実施（テスト未実施）
- **エビデンスの保存**: `qa-tests/phase1/evidence/` 配下にログファイル、スクリーンショット、テストレポート等を保存。命名規則: `{タスク番号}-{内容}.{拡張子}`

## テストシナリオの記載形式

### ユニットテスト確認（表形式）

| No | 手順 | 確認項目 | 期待値 | 結果 | 備考 |
|----|------|---------|--------|------|------|
| 1 | pnpm test vibe-kanban-client.test.ts 実行 | テスト実行 | すべてのテストが成功 | - | - |
| 2 | - | カバレッジ確認 | カバレッジ90%以上 | - | - |

**重要**:
- 手順は自然言語で簡潔に記述（例: 「pnpm test 実行」「カバレッジ確認」）
- 技術的なコマンドは記載してもよいが、自然言語での説明も併記

### API/CLIテスト（簡潔な表形式 + curlコマンド）

| No | 手順 | 確認項目 | 期待値 | 結果 | 備考 |
|----|------|---------|--------|------|------|
| 1 | pnpm task:loop --issue 103 実行 | タスクループ起動 | エラーなく起動 | - | - |
| 2 | - | attempt ID表示 | "attempt: {実際のID}" と表示 | - | - |
| 3 | - | Claude Code起動 | Claude Codeが正常に起動 | - | - |

**実行例**:
```bash
# タスクループ実行
pnpm task:loop --issue 103

# ビルド確認
pnpm build
```

### テスト実行

```bash
# ユニットテスト
pnpm test vibe-kanban-client.test.ts

# カバレッジ付きテスト
pnpm test:coverage vibe-kanban-client.test.ts

# ウォッチモード
pnpm test:watch vibe-kanban-client.test.ts

# 全テスト
pnpm prepush
```
